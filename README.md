# 孤星 LONESTAR

**一个零依赖、单文件、双击即开的深空生存 Roguelite。同一份源码同时产出网页版和微信 / 抖音小游戏版。**

> 打开 `index.html` → 选「闯关」或「无限」→ 活久一点。

没有 npm install，没有构建服务器，没有外部图片/音频/字体资源。整个游戏是 **一个 361 KB 的 HTML 文件**——拷到 U 盘、发到微信、丢进任意浏览器，它都能跑。断网也能跑。


## 立刻开始

**方式一（推荐）**：双击 `index.html`。就这样。

**方式二**：如果浏览器对 `file://` 有洁癖，起个本地服务器：

```bash
npm start          # → http://127.0.0.1:5178/
```

## 两种模式

| | **闯关模式** ❖ | **无限模式** ∞ |
|---|---|---|
| 结构 | 5 章 × 5 波 = **25 波**，有终点 | 波次不封顶 |
| Boss | 每章末一只，第 25 波是**最终 BOSS「终焉 · 星蚀」** | 每 5 波一只，4 种循环加血 |
| 结局 | 打完第 25 波 → **通关结算** | 唯一结局是死亡 |
| 奖励 | **星尘**（与之前完全相同的公式）+ 每章通关奖励 | **涂装皮肤**（不产出星尘） |
| 关卡选择 | 已通关的章节可直接开局（自动补偿免费强化） | — |

两种模式共用同一套波次数值曲线，所以「第 12 波」在两边一样难。

> **设计取舍**：星尘只由闯关模式产出，无限模式的奖励是皮肤进度。如果你希望无限模式也掉一点星尘，改 `src/js/80-ui.js` 的 `Save.recordRun()` 里 `mode === 'endless'` 分支即可。

## 涂装皮肤（12 种）

无限模式的里程碑会解锁新的**飞船涂装**，每种同时改变 **船体外形** 与 **弹道样式**，点一下立刻生效：

- **6 种船体外形** —— 箭形 / 细长拦截机 / 圆盘侦察舰 / 晶体护卫舰 / 蝠翼战机 / 星芒舰
- **5 种弹道样式** —— 脉冲光弹 / 能量球 / 晶片 / 波动 / 星芒

| 涂装 | 解锁条件 |
|---|---|
| 先驱者 | 默认拥有 |
| 黄蜂 · 泡泡 · 翡翠 · 紫电 | 无限模式到达第 8 / 15 / 22 / 30 波 |
| **奇点**（船体和子弹会一直变色） | 无限模式到达第 40 波 |
| 霜寒 | 单局最高连击 45 |
| 烈阳 | 单局击杀 800 |
| 虚空 | 单局得分 60,000 |
| 血月 | 累计击杀 12 只 Boss |
| 神盾 | 累计星尘 900 |
| 星云 | 通关闯关模式全部 5 章 |

未解锁的皮肤会显示**进度条**和还差多少。涂装界面里每张卡都有一个**实时预览画布**——飞船和弹道都在动。

## 成就系统（37 个）

### 设计意图

1. **补上经济缺口** —— 之前星尘只能从闯关模式产出，只打无限模式的玩家永远买不起机库强化。成就成为星尘的第三个来源（合计 **✦5,720**，机库买满约需 ✦6,300），把这条闭环接上。
2. **覆盖不同动机** —— 六个分类对应六种玩家：推进度的、刷输出的、玩构筑的、收集的、自虐的、找彩蛋的。
3. **进度可验证** —— 每个成就都必须能用一个**纯函数** `get(ctx)` 算出当前进度值。进度条、解锁判定、自动化测试三者共用同一份真相，不会出现"显示已达标却没解锁"。

### 六个分类

| 分类 | 数量 | 例子 |
|---|---|---|
| ❖ **进程** | 7 | 初次接触（清空第一波）· 深潜 / 深渊行者 / 触底（无限模式 10/20/30 波）· 第一章 · **神性**（通关全部 5 章）|
| ⚔ **战斗** | 9 | 百人斩 / 千人斩 / **万人斩** · 猎手 / 守卫屠夫（累计 5 / 25 只 Boss）· 连击大师（60 连击）· 暴击狂人（5000 次）· 百万输出 · **千钧一发**（低于 5% 血量清空一波）|
| ⚙ **构筑** | 6 | 传说降临 · 满级 · 满载（单局 30 次强化）· **百科全书**（集齐 36 种）· **六边形战士**（无人机+导弹+环绕+连锁+爆炸+跳弹）· 赌徒 |
| ✦ **收集** | 5 | 涂装收藏家 / **全涂装** · 机库满仓 · 星尘富翁 · 图鉴全开（击杀全部 9 种敌人）|
| ◈ **挑战** | 5 | 毫发无伤（连续 3 波不吃伤害）· **完美章节**（整章无伤）· 一命通关（不用逃生舱）· 赤手空拳（前 5 波不拿强化）· 速通（5 分钟到第 10 波）|
| ? **隐藏** | 5 | 摸鱼（主菜单停留 3 分钟）· 出师未捷（第 1 波就死）· 静音修行 · 观察者（F3 看 60 秒）· 马拉松（单局 30 分钟）|

四档稀有度：**铜** ✦25 / **银** ✦60 / **金** ✦150 / **铂** ✦400。

**隐藏成就在解锁前显示为「？？？」**，描述也是遮罩的——它存在的意义就是让你在某次意外操作后突然看到那个提示弹出来。

**全成就**（解锁其余 36 个）额外奖励 **✦1000**，并在主菜单显示金色徽章。

### 界面

主菜单按 `J` 打开成就界面：

- 顶部：完成度进度条 + `已获得 ✦N` / `还能拿 ✦N`
- 七个分类标签，各自带 `已完成 / 总数` 计数
- 卡片网格：图标、名称、稀有度、描述、进度条（`742 / 1000`）、奖励
- **未完成的排在前面**，已完成的沉底
- 隐藏成就带 `secret` 灰化遮罩

解锁时会**在游戏内即时弹提示**（图标 + 名称 + `✦ +奖励`），不需要回到菜单才发现。

### 统计层

成就判定依赖存档 v3 新增的 `stats` 层，记录三类数据：

- **累计**：击杀 / Boss / 时长 / 冲刺 / 暴击 / 伤害 / 强化次数 / 重抽 / 传说卡 / 满级卡 / 死亡 / 星尘总收入 / 清空波次 …
- **单局最佳**：最远波次（两种模式分开记）/ 最高分 / 最高连击 / 最多强化 / 最长无伤连波 / 最长存活 …
- **集合**：见过哪些强化卡、杀过哪些敌人

其中一部分（强化次数、传说卡、图鉴、清空波次）是**即时写入**的，所以解锁提示能在对局中途弹出来；另一部分在每局结束时一次性折算。

## 存档

### 局内存档：玩累了可以暂停存档，下次接着打

**这是给"没打完的这一局"用的。**

按 `P` 暂停 → 点「**保存并退出** <kbd>S</kbd>」→ 回到主菜单。下次打开时，主菜单最上方会出现一张绿色的「**继续**」卡片：

```
▶ 继续 无限模式
  第 12 波 · 8,420 分 · 213 击杀 · 4:31
  3 分钟前存档 · 7 次强化 · 船体 186
```

点一下就直接回到第 12 波接着打。**闯关模式和无限模式各有一个独立存档槽**，可以同时存在两份，两张卡片并排显示。不想要了就在卡片右边点 `✕` 丢弃。

**存档内容**：模式、章节、下一波次、分数、击杀、用时、最高连击、**完整属性表**、全部已选强化与层数、船体与护盾、逃生舱剩余次数、重抽次数、火力过载剩余时间、已装备皮肤。

**不存的内容**：场上的敌人、弹幕、地雷、光束。**读档后从当前这一波的开头重打**（船体与分数保留，并给你 2.6 秒出生保护）。这是同类作品的通行做法——序列化 Boss 状态机和各种弹幕的边界情况远比它带来的收益麻烦。

**自动存档**：开新局时、每清空一波时、按暂停时，都会自动覆盖该模式的槽位。所以就算你直接关掉浏览器，"这一波白打"也最多损失一波。

**什么时候会清掉存档**：阵亡、通关、主动点「放弃远征」时，对应模式的槽位会作废（因为这一局已经结束了）。开新一局会覆盖同模式的旧存档，覆盖前会弹确认。

### 进度存档（账号级）

**存在本机浏览器（localStorage），不联网、不上传。** v3 结构覆盖：

- 两种模式各自的最高分 / 最远波次 / 最佳击杀 / 最佳连击
- 闯关模式的**章节解锁与通关记录**、每章最佳分
- **12 种涂装的解锁状态与当前装备**
- **37 个成就的解锁记录** + 完整的累计/最佳统计层
- 机库永久强化等级、累计星尘、总击杀、Boss 击杀、总时长
- 静音设置、最近一次构筑

主菜单 →「存档 <kbd>S</kbd>」可以：

- **导出到文本框** —— 复制这段 JSON 就是完整备份
- **从文本框导入** —— 换电脑 / 换浏览器时粘贴回来即可；非法 JSON 或未知版本会被拒绝且**不会破坏现有存档**
- **清除全部存档**（同时清掉两份局内存档）

旧版 `v1` / `v2` 存档会在首次读取时**自动迁移**（最高分 / 最远波次归入无限模式，机库与星尘原样保留，旧的扁平计数折进新的统计层，并按新统计补发已达成的成就）。

> 两份存档用不同的 key：账号进度存 `starfall.save.v3`，局内存档存 `starfall.run.v1`。读取时会依次回退尝试 `starfall.save.v2` / `starfall.save.v1` 并自动迁移。

## 小游戏版与广告接入

网页版的全部玩法、存档、成就、皮肤都原样搬进了小游戏，**没有裁剪任何内容**。区别只在两处：UI 从 DOM 改成 Canvas 绘制，音效从 `AudioContext` 换成 `wx.createWebAudioContext()`。

### 一份代码，三个平台

平台差异全部收在 `src/js/05-platform.js` 一个文件里：

| 能力 | 浏览器 | 微信 | 抖音 |
|---|---|---|---|
| 画布 / 主循环 | `document` / `window.rAF` | `wx.createCanvas()` / `GameGlobal` | `tt.createCanvas()` / `GameGlobal` |
| 存档 | `localStorage` | `wx.setStorageSync` | `tt.setStorageSync` |
| 音频 | `new AudioContext()` | `wx.createWebAudioContext()` | `tt.createWebAudioContext()` |
| 触摸 / 分享 / 震动 / 剪贴板 | 浏览器 API | `wx.*` | `tt.*` |

`App` 构建时会自动判断平台，游戏逻辑（`60-game.js`）**完全不知道自己在哪跑**。
小游戏里没有 DOM，所以 UI 层有两套实现，但导出**同一个 `UI` 接口**：

- `src/js/80-ui.js` —— 浏览器用的 DOM UI（构建时被拆掉，不进小游戏包）
- `src/js/86-ui-canvas.js` —— 小游戏用的 Canvas UI（菜单 / 章节 / 涂装 / 机库 / 成就 / 存档 / 三选一 / 暂停 / 阵亡 / 通关 + 摇杆 + 冲刺键）

### 广告系统（`src/js/82-ads.js`）

| 广告位 | 触发位置 | 玩家得到 | 每日 | 单局 |
|---|---|---|---|---|
| `revive` | 阵亡结算「看广告复活」 | 原地满血复活，这一局作废 | 10 | 1 |
| `skin` | 涂装界面锁着的皮肤上 | 免费解锁该涂装 | 3 | — |
| `doubleDust` | 阵亡结算「看广告双倍星尘」 | 本局星尘 ×2 | 20 | 1 |
| `reroll` | 三选一界面「看广告重抽」 | 免费换一批卡 | 30 | 8 |
| `interstitial` | 每 3 局结束后 | —（被动） | — | 每 3 局 1 次 |
| `banner` | `Ads.showBanner()` | —（被动） | — | — |

接入只有一步：把 `src/js/82-ads.js` 顶部 `AD_UNITS` 里的 `adunit-xxxx` 换成后台申请到的 ID。
TapTap 不一样 —— 它的广告位 ID 不来自后台手填，而是服务端下发（激励视频 / 插屏 / Banner 共用一个），
用 MCP 查出来填进 `AD_UNITS.taptap` 即可（孤星当前是 `1054323`，横屏）。

```js
const r = await Ads.show('revive');
// r.ok       true = 真正看完了，这时才发奖励
// r.reason   ok | not-ended | aborted | unavailable | disabled
//            | daily-limit | run-limit | cooldown | unknown-placement | error | timeout
```

几条刻意的设计：

- **只有 `isEnded === true` 才发奖励**，中途划掉一律不发 —— 平台合规要求，也防刷。
- **ID 没填不会崩。** `unitIdOf()` 发现还剩 `xxxx` 就返回空串，`isSupported()` 变 false，所有调用立刻返回 `unavailable`，游戏走「不支持广告」分支 —— 复活按钮不显示、涂装只能用星尘买。**提审前忘配广告也不会白屏。**（TapTap 的 ID 来自服务端，已经填好，不走这条兜底。）
- **限次策略是数据不是代码。** 每日 / 单局上限写在 `CONFIG.limits` 里，改数字即可（`daily: 0` = 当日不限制）。
- **单局额度是「每局一次」，不是「整个会话一次」。** `Ads.beginRun()` 在 `Game.startRun()` / `Game.continueRun()` 里清零单局计数 —— 每开一局都重新拿到自己的额度。这条曾经真的坏过：`beginRun()` 早先只在 Canvas 版被调用，DOM 版（网页 / TapTap）的计数永不清零，于是 `perRun: 1` 退化成"一辈子只能看一次"。现在 `test/taptap.mjs` 专门守着它。
- **广告失败不能让玩家干等。** 加载 12 秒超时、观看 90 秒超时、失败自动重试 1 次，任何异常都落回 `unavailable`。
- **浏览器里自动进 mock 模式**（`CONFIG.mock === 'auto'`），弹 `confirm()` 让你选「看完 / 中途关闭」，全流程本地就能调通；自动化测试用 `Ads.setDevHandler(fn)` 注入判定。判据是「有没有原生广告 API」（`Platform.hasAdApi`），不是「是不是小游戏」—— 因为 TapTap 是 H5 形态却有真实广告能力。

### 广告引入了什么复杂度：结算时机

「看广告复活」逼着解决一个问题：**复活后这一局还没结束，不能提前记账。** 两套 UI 用了两种做法，结果一样（这一局只记一次账）：

**Canvas 小游戏版（微信 / 抖音）：结算推迟到离开死亡界面时**

```
死亡 → 记死亡预览（不落账）→ 玩家选择 ┬─ 看广告复活 → 回到场上（这一局还没结束）
                                      ├─ 看广告双倍 → 先落账再 ×2
                                      └─ 回主菜单 / 开新局 → 落账
```

**DOM 版（网页 / TapTap）：死亡即刻结算 + 复活时回滚**

```
死亡 → 照常结算（星尘立刻入账，关掉页面也不丢）→ 玩家选择 ┬─ 看广告复活 → 用快照把这次结算回滚 → 回到场上
                                                          └─ 再次远征 / 主菜单 → 保持已结算
```

DOM 版之所以不照抄 Canvas 版，是因为网页版玩家**随手关标签页**很常见：结算一旦推迟，死在结算界面上就白打了。
所以这里反过来做 —— 先落账（`Save.snapshotForRevive()` 留一份快照），确认玩家真看完广告复活了再
`Save.rollbackForRevive()` 把这一局撤回来。快照同时包含「账号进度」和「没打完的这一局」，
因为 `finalizeRun()` 会把局内存档一起清掉。

无论走哪条路径，`Game.finalizeRun()` 都是幂等的，这一局只会被记一次。两种做法各有专门的测试守着
（`test/minigame.mjs` 与 `test/taptap.mjs`）。

## 操作

| 按键 | 作用 |
|---|---|
| `W` `A` `S` `D` / `↑↓←→` | 推进器移动 |

| `S`（暂停时） | 保存并退出——下次从主菜单「继续」接着打 |
| `Q`（暂停时） | 放弃远征（会清掉这一局的存档） |
| `Enter` / `E` | 主菜单：打开章节选择 / 直接开始无限模式 |
| `K` / `H` / `S` / `J` | 涂装皮肤 / 机库 / 存档 / **成就** |
| `?` | 操作说明 |
| `M` | 静音 / 恢复 |
| `F3` | 性能读数（FPS / 粒子数 / 精灵缓存数） |

触摸设备会自动显示虚拟摇杆与冲刺键，瞄准交给自动索敌。

## 玩法

**核心循环**：清空一波 → 从三张强化卡里挑一张 → 下一波更强 → 每 5 波一只 Boss → 结算拿星尘或皮肤进度 → 去机库买永久强化 / 换套涂装 → 再来。

**9 种敌人**，每种一套独立 AI：

| 敌人 | 行为 |
|---|---|
| 游荡者 | 直线追击，带正弦摆动 |
| 疾锋 | 接近后**红色蓄力预警**，然后锁定方向高速突进 |
| 炮舰 | 保持距离绕圈，齐射瞄准弹 |
| 裂体 | 死亡时分裂成 3 只微光 |
| 微光 | 高速群聚，弱但烦 |
| 布雷者 | 中距离游走并丢下感应地雷 |
| 织网者 | 绕你公转并持续喷螺旋弹幕 |
| 环绕者 | 维持固定半径，切向三连射 |
| 重装 | 高护甲，蓄力后 700px/s 冲撞 |

**4 个 Boss**，每个有 4–5 套招式，血量 30% 以下进入狂暴：

- **守卫者** — 多环全向弹幕 / 螺旋弹雨 / 召唤 / 扫射光束
- **裂解母体** — 不断产卵 / 冲撞 / 死后连环爆炸
- **湮灭棱镜** — 相位跳跃 + 落地弹幕 / 折射光束
- **星蚀** — 生成**引力井**把你往里拽 / 全向弹幕 / 召唤
- **终焉 · 星蚀**（闯关模式第 25 波）— 1.7 倍血、1.15 倍速、3 倍分

**36 张强化卡**，4 个稀有度（常规 / 稀有 / 史诗 / 传说），每张最多叠 3–8 层。部分例子：

- 常规：强化炮管、快速装填、装甲板、牵引光束、应急纳米机
- 稀有：分裂炮口、穿甲弹芯、荆棘力场、连锁电弧、护卫无人机、连击延展
- 史诗：爆裂弹头、跳弹、**湮灭光环**（环绕刀刃）、时间涟漪、护盾过载、死亡爆发
- 传说：**奇点引擎**（每 9 杀生成黑洞）、恒星核心、无尽弹幕、虚空协议、处决协议

**10 项机库永久强化**（星尘购买，跨局保留）：强化船体、武器校准、应急护盾、备用推进剂、星图导航、残骸回收、预装模块、**逃生舱**（每局原地复活）。

**其它系统**：连击倍率（最高 x5，受伤清零）、能量核心拾取（分数 + 护盾）、偶尔掉落的修复包与火力过载、局内重抽、6 条随机死亡文案。

### 波次与强度墙

两种模式共用一条数值曲线：Boss 每 5 波一只，敌人血量按 `1 + (w-1)×0.235 + max(0, w-6)^1.62 × 0.022` **无限增长**。

跑 `npm run report` 可以打印完整的逐波强度表、Boss 轮换表和「每波只拿一张卡、贪婪按 DPS 选牌」的真实成长模型。

> **这个模型必须跑够多次数才有意义。** 40 次模拟时，同样的代码连续跑两次给出的中位数分别是第 **23** 波和第 **62** 波 —— 抽卡随机性太大，单次结果完全是噪声。报告里现在跑 **240 次**（约 5 秒），中位数才稳定下来：**软墙在第 25–27 波**，10% / 90% 分位是第 11 波和第 92 波。**构筑好坏能把结果差出四倍以上。**

顺带说明一下这个数字意味着什么：**闯关模式的 25 波几乎正好压在软墙上** —— 一个中规中矩的构筑能通关，但第 25 波那只 1.7 倍血的最终 BOSS 会真的卡住一半的人。这是有意的：最终 BOSS 应该像一堵墙。如果你觉得太狠，调 `src/js/40-content.js` 里的 `waveScale()` 即可；`waveBudget()` 控制数量节奏。


### 收尾防卡死

这条是**被真实的端到端测试逼出来的**：无头浏览器在第 25 波连卡 14 个批次，场上只剩 1 只布雷者 —— 它在中距离游走，而玩家蹲在竞技场角落不动，于是它永远待在射程外，`waveState` 卡在 `clearing`，通关永远不来。

修法是两道保险，都在"清场阶段"（刷怪队列已空、场上还有残敌）生效：

1. **软性**：残敌的远距离追赶补偿随时间递增。原来只有两档（>820px 时 ×1.6），现在前 3 秒不变，之后每多拖 1 秒再加 0.55（上限 +6.6×）。因为加速只作用于 820px 之外（本来就出屏了），玩家看不到任何突兀的加速。
2. **硬性**：拖到 22 秒，把仍在 1100px 之外的敌人直接挪到视野边缘，配一圈生成特效和音效 —— 玩家看得见它从哪来，而不是永远等一只不出现的怪。

`npm test` 里有个用例专门复现这个局面：清掉场上所有敌人，只留一只布雷者扔到 2480px 外，然后把玩家钉在另一个角、只对准星不给移动输入，断言这一波最终仍然会清掉。上面提到的两条渲染截图里的"高波次混战"也是同一套自动化跑出来的。

- **Boss 波 5/10/15/20** 各自打到清场

- **闯关模式**：跑完第 1 章 → 章节标记 / 解锁第 2 章 / 星尘 + 章节奖励入账

### `npm run test:minigame` 做了什么

小游戏跑不起来 DOM，所以这个测试**先把 DOM 拿掉**：造一个 `wx` / `tt` / `GameGlobal` 运行时 mock
（**没有 `document`、没有 `window`、没有 `localStorage`**），然后把 `app/js/bundle.js` 加载进去，
确认它在这个环境里真的能跑：

- 入口 `game.js` 能被 `require` 并成功 `boot()`，画布、触摸、存储、音频全部走 `wx.*`
- **Canvas UI 的十套界面逐个打开并真的画出来**：主菜单 / 章节 / 涂装 / 机库 / 成就 / 存档 / 三选一 / 暂停 / 阵亡 / 通关。
  验证方式是给 2D 上下文桩加一个**落墨计数器**（`fill` / `stroke` / `fillText` / `drawImage` …），
  每套界面单独 tick 两帧后断言落墨次数 > 0、且各自登记了**数量不同**的可点区域 —— 证明它是真的在画，而不是"调用了 draw 就算过"
- 摇杆与冲刺键的触摸坐标 → 输入状态映射正确
- **存档走 `wx.setStorageSync`**：暂停 → 保存退出 → 重新加载 bundle → 继续卡片确实读得回来
- **广告全流程**（注入假广告位 ID，模拟真实 SDK 回调）：
  - 看完 → 发奖励；**中途关闭（`isEnded: false`）→ 不发奖励**
  - 每日上限 / 单局限次 / 冷却时间都会被正确拦截
  - 加载失败 → 自动重试 → 仍失败则返回 `unavailable`，游戏不卡死
  - **复活后再次阵亡，这一局只记一次**（星尘与统计都不翻倍）—— 这是 `finalizeRun()` 的存在意义
  - 广告位 ID 仍是 `xxxx` 占位符时，`isSupported()` 为 false 且所有调用返回 `unavailable`
- 切后台 / 回前台（`wx.onHide` / `wx.onShow`）不崩、不跳帧

### `npm run test:taptap` 做了什么

TapTap 是**H5 形态**（DOM 在，宿主只注入一个全局 `tap`），所以这个测试把**网页版产物**跑在
「桩 DOM + 桩 tap」里（`test/taptap.mjs`，57 项断言）：

- 平台识别为 `taptap`，且**不被误判成小游戏**：`isMini === false`、存储仍走 `localStorage`、界面仍是 DOM
- 广告 API 就是宿主注入的 `tap`（`Platform.adApi === tap`），**不走 mock**
- 广告位 ID 全链路透传：`AD_UNITS.taptap` → `tap.createRewardedVideoAd({ adUnitId })`
- **阵亡界面出现「看广告复活」按钮**，点击后：广告回调 `isEnded` → 发奖励 → 原地复活、回到对局
- **复活把死亡时的那次结算回滚**：`runs` 与星尘都精确回到死亡前的值，再死一次只记一次账
- 中途关掉广告：不发奖励、不计次、**不回滚**（这一局仍然是已结算，玩家可以直接再来一局）
- 单局 1 次用掉后按钮消失；没有 `tap` 的普通浏览器仍然 `isSupported() === false` + mock 兜底

### `npm run test:browser` 做了什么

因为桩环境证明不了"真机能跑"，所以另起一个**真实无头 Chrome**，用 DevTools Protocol：

- 捕获所有 `console` 输出与未捕获异常 → 断言**零错误零异常**
- 用真实 `requestAnimationFrame` 跑 1500 帧
- **查 DOM 布局**：主菜单面板居中、无溢出、12 个控件都在视口内；三张强化卡是 `341×251` 并排、互不重叠、动画结束后不透明
- **5 种分辨率回归**（1920×1080 → 820×600）：无横向溢出、控件不越界、面板装得进视口
- **双模式入口**：两张模式卡尺寸与进度文案；章节选择列出 5 章且初始只解锁第 1 章
- **涂装界面**：12 张卡 + 12 个预览画布，读取画布像素确认**真的画出了内容**（非黑像素占比）；点击装备 → 新开一局皮肤生效 → 对局中发射的子弹用上了新弹道
- **存档往返**：导出到文本框 → 清档 → 导入 → 星尘 / 波次 / 涂装 / 章节全部还原且已落盘；非法 JSON 给出错误提示且不破坏存档
- **通关流程**：真实 rAF 下从第 5 章打到第 25 波，最终 BOSS 出现、通关界面显示、5/5 章记录
- **局内存档跨刷新**：暂停 → 点真实的「保存并退出」按钮 → 主菜单出现继续卡片 → **`Page.reload` 真的刷新整个页面** → 卡片仍在 → 点击后逐项核对波次 / 分数 / 击杀 / 构筑 / 属性表确实接上了，再继续打 2500 帧确认不卡死
- **双槽位**：刷新后分别存下闯关与无限两局，主菜单同时显示两张卡片，点闯关那张能正确回到对应章节

## 技术取舍

| 问题 | 做法 |
|---|---|
| 既要模块化源码，又要双击即开 | `build.mjs` 把 12 个模块内联进一个 IIFE，产物是单文件；同时导出 bundle 供测试直接 eval |
| 发光效果很贵 | 不用 `shadowBlur`，改为**预渲染辉光精灵 + `lighter` 混合**，按色相量化（8°一档）缓存，全场只创建几十张离屏 canvas |
| 粒子会 GC 抖动 | 3000 容量对象池 + 交换删除，零分配 |
| 弹幕 vs 敌人碰撞 | 竞技场做了边界，直接 O(n·m) 双循环；实测 9000 帧压力下 ~2ms/帧 |
| 没有音频资源 | 全部振荡器 + 噪声缓冲实时合成；配乐是一个按 16 分音符调度的生成式序列，BPM 与强度随波次上升 |
| 皮肤要能改外观 | 皮肤是**纯数据**（形状名 + 色相 + 弹道名），绘制端用 `drawShip()` / `drawBulletShape()` 两个 `switch` 消费；加新皮肤只需往数组里加一条 |
| 成就进度要可信 | 每个成就只有一个纯函数 `get(ctx)`；进度条、解锁判定、自动化测试全部读它，不可能出现三者不一致 |
| 加成就不能把存档搞坏 | 存档升到 v3，旧的顶层计数统一折进 `stats` 层；读取时依次回退 v2 / v1 的 key 并自动迁移，迁移后立刻按新统计补发已达标成就 |
| 涂装预览要动起来 | 每张卡一个 `<canvas>`，复用游戏本体的绘制函数，每帧重画 12 个小画布（实测开销可忽略） |
| HUD 每帧刷新会抖 | 脏检查式写入，值没变就不碰 DOM |
| 字号要能整体调 | 单一 `--fs` 倍率变量 + `calc()`，容器与图标跟着一起缩放，不出现"字大了框没大" |
| 矮屏放不下菜单 | 三档 `max-height` media query 逐级隐藏非关键元素（模式卡描述 → 图标 → 统计行 → 页脚） |
| 存档要能备份 | 账号进度导出成 JSON 文本 / 从文本导入，带版本校验与 v1 自动迁移；读写全程 try/catch，隐私模式下静默降级 |
| 没打完的一局要能存 | 局内存档与账号存档**分开两个 key**；只序列化"这一局的进度"而不含场上实体，读档时从当前波次开头重打 —— 避开了序列化 Boss 状态机 / 光束 / 地雷的一堆边界情况 |
| 存档被改坏会怎样 | 所有字段在读入时过一遍 `Number.isFinite` 消毒并 clamp 到合理区间；版本号不对直接丢弃；`applySnapshot` 对 `null` / 缺字段 / 字符串数字都能安全兜底 |
| 切标签页回来会死 | `blur` / `visibilitychange` 自动暂停；`dt` 上限 0.05s |
| 音频自动播放被拦 | 首次真实按键/点击时才创建 `AudioContext` |
| 一份源码要出三个平台 | 平台差异全部收进 `05-platform.js` 一层适配（画布 / 触摸 / 存储 / 音频 / 生命周期 / 分享 / 震动）；游戏逻辑只调 `Platform.*`，不知道自己在哪跑 |
| 小游戏里没有 DOM | UI 拆成两套实现共用一个接口：`80-ui.js`（DOM）与 `86-ui-canvas.js`（Canvas）。`build-minigame.mjs` 在构建时按 ASCII 锚点把 `80-ui.js` 切成两半，只保留存档部分，缺锚点直接**大声报错**而不是悄悄产出坏包 |
| 小游戏包的体积 | 同一份源码两份产物：网页版内联 HTML，小游戏版只留 `js/bundle.js`（约 320 KB，主包上限 4 MB） |
| 广告不该污染游戏逻辑 | `82-ads.js` 是一个独立服务，对外只暴露 `show(placement) → {ok, reason}`；限次、超时、重试、平台差异全在里面。游戏侧只判断"看完没看完" |
| 广告 ID 没配会不会崩 | 不会。`unitIdOf()` 发现 ID 里还有 `xxxx` 就返回空串 → `isSupported()` 为 false → 所有调用立刻返回 `unavailable`，游戏走"不支持广告"分支。**可以先提审再配广告** |
| 看广告复活会让一局结算两遍 | 结算改成**幂等**的 `Game.finalizeRun()`，从"死亡瞬间"挪到"离开死亡界面时"；死亡只写一个预览值。无论玩家走复活 / 双倍 / 直接退出哪条路，这一局只记账一次 |
| 残敌够不着，这一波清不掉 | 两道保险：清场阶段残敌的远距离追赶补偿**随时间递增**（3 秒后开始涨，最多 +6.6×），拖到 22 秒还有硬托底 —— 把仍在 1100px 外的敌人挪到视野边缘并放一圈生成特效。见下面的"收尾防卡死" |

**打击感细节**：命中顿帧（hit-stop）、按伤害缩放的屏幕震动、暴击白闪、受击时把附近弹幕吹开、冲刺无敌帧、低血量脉冲红边、Boss 死亡连环爆炸、连击里程碑、通关时的 140 粒金色礼花。
